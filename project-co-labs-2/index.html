Program rationale

Mathematical training, translated into practice.

The program does not ask students to learn twelve unrelated subjects. It begins with a common computational and statistical core, then guides each team through focused domain revision, model development, validation, and communication. The result is a credible project portfolio that demonstrates analytical depth as well as professional execution.

12industry-relevant project choices
3weeks of common foundation
8–10weeks from discovery to showcase
4–5students per multidisciplinary team

Learning architecture

One shared journey, tailored specialisation.

Each stage intentionally narrows the focus: students first acquire dependable working habits, then revise the mathematics most relevant to their selected track, and finally deliver an end-to-end solution.

Common foundation

Python, data handling, visualisation, reproducibility and collaborative Git workflows.

Domain revision

Refresh the mathematical and statistical tools that drive the chosen project.

Problem framing

Define the business question, success criteria, data scope, risks and baseline.

Implementation

Build, evaluate and refine a transparent, well-tested analytical solution.

Industry delivery

Present a portfolio-quality repository, demo and decision-oriented narrative.

Stage I · weeks 1–3

Common foundation for every participant.

This is a practical revision sprint. Every student completes the same core so that project teams can work efficiently and apply a consistent standard of analysis.

Core capabilities

  • Python & notebooks: functions, modules, environments and readable code.
  • Data work: NumPy, Pandas, data quality checks, joins, missing values and feature preparation.
  • Visualisation: distributions, trends, diagnostics and charts that tell an honest story.
  • Statistical practice: sampling, inference, regression, classification metrics and experiment design.
  • Computational mathematics: vectors, matrices, eigendecomposition, numerical optimisation and simulation.
  • Professional workflow: Git/GitHub, issue tracking, documentation, code review and reproducibility.

Weekly foundation rhythm

Week 1Python, Jupyter, NumPy, Pandas and exploratory data analysis. Output: cleaned dataset and short EDA report.
Week 2Statistical modelling, visualisation, validation, SQL basics and Git collaboration. Output: baseline model notebook.
Week 3Optimisation, simulation, APIs/apps and project discovery. Output: problem brief, team charter and initial backlog.

Stage II · project tracks

Twelve projects, grouped by the decisions they improve.

Teams select one project according to interest and readiness. Each track has a clear decision context, a measurable modelling problem and a recommended technical focus.

Credit Risk Prediction

Estimate default risk while handling imbalanced data, calibration, fairness and interpretable credit decisions.

Revise: logistic regression, Bayes, ROC/AUC, calibration, scorecards.

Portfolio Optimisation

Construct and compare portfolios under return, risk, transaction-cost and allocation constraints.

Revise: covariance, convex optimisation, CAPM, Monte Carlo, risk measures.
 

Dynamic Pricing

Recommend prices from demand, competition and elasticity while respecting commercial guardrails.

Revise: regression, elasticity, causal thinking, bandits, optimisation.
 

Supply Chain Optimisation

Balance inventory, service levels and costs through forecasting and constrained planning.

Revise: linear programming, networks, EOQ, simulation, forecasting.
 

Recommendation System

Personalise rankings using user–item behaviour, content signals and offline evaluation.

Revise: linear algebra, similarity, matrix factorisation, ranking metrics.
 

Time Series Forecasting

Forecast sales, demand or traffic with uncertainty-aware models and rolling validation.

Revise: ARIMA, state space models, seasonality, error metrics.
 

Fraud Detection

Identify suspicious transactions using anomaly detection and cost-sensitive classification.

Revise: hypothesis tests, classification, imbalance, anomaly detection.
 

Customer Segmentation

Find actionable customer groups and turn behavioural patterns into retention strategies.

Revise: clustering, PCA, distributions, statistical profiling.
 

Graph Analytics

Analyse relationships and influence in networks for communities, fraud rings or recommendations.

Revise: graph theory, centrality, random walks, spectral methods.
 

LLM Application

Build a responsible retrieval-based assistant with evaluation, citations and safety boundaries.

Revise: embeddings, information retrieval, evaluation, prompt design.
 

Greeks Calculator & Option Pricing

Price options and visualise sensitivity to market inputs through an interactive analytical tool.

Revise: stochastic calculus, Black–Scholes, PDEs, numerical methods.
 

Route Planner

Design efficient routes under distance, time, capacity and delivery-window constraints.

Revise: graph algorithms, shortest paths, integer programming, heuristics.

Stage III · execution

From a viable question to a defensible solution.

The implementation phase uses short review cycles. Progress is assessed by clarity of reasoning and learning—not merely by model complexity.

Weeks 4–5 · Discovery & data Frame the problem

Write a one-page project charter; identify stakeholders, decision metrics, data sources, ethical risks and a simple baseline. Complete data audit and exploratory analysis.

Weeks 6–7 · Modelling & validation Prove the value

Engineer features, train transparent benchmark and advanced models, test assumptions and compare against appropriate baselines using agreed evaluation metrics.

Weeks 8–9 · Productisation Make it usable

Refactor the solution, add documentation and tests, build a lightweight dashboard/API/notebook interface, and prepare an executive-facing story.

Week 10 · Showcase & reflection Present with confidence

Demonstrate the working project, defend design choices, explain limitations and publish a clean GitHub portfolio package.

Quality framework

Assessment that rewards both rigour and relevance.

Each project is reviewed at defined checkpoints. Evaluation makes room for technically ambitious work while retaining a high standard for reproducibility, responsible practice and communication.

 

Project workflow

1. Scope before coding
Agree the user, decision, data boundary and success measure. Record assumptions and risks in the project charter.
2. Establish a baseline
Start with a simple, interpretable approach. Advanced methods should improve a stated metric or solve a stated limitation.
3. Review and iterate
Use a weekly stand-up, fortnightly faculty/mentor review and issue tracker. Keep experiments and decisions traceable.
4. Package the result
Deliver a repository that another student can run, a short technical report and an accessible stakeholder demo.

Suggested team structure

Project lead

Owns scope, cadence and stakeholder narrative.

Data lead

Owns data audit, pipeline and documentation.

Modelling lead

Owns methods, experiments and validation.

Product lead

Owns demo, visuals and final presentation.

A peer review system

The program is designed around deliverables that students can confidently show to recruiters, collaborators and future project sponsors.

Problem brief Decision context, user, data scope, success metric and assumptions.
Reproducible repository Structured code, setup instructions, data provenance and experiment record.
Technical report Methods, validation, results, limitations and ethical considerations.
Working demonstration Notebook, dashboard or lightweight app that makes the insight tangible.
